# 个人财务概览与轻量记账

Status: ready-for-agent

## Problem Statement

使用者的可用资金、投资、借贷和每月支出分散在不同地方，难以看清当前净资产、日常消费是否超额，以及现有可用资金能覆盖几个月的计划支出。使用者希望手动维护这些数据，日常记账只填金额和备注。

## Solution

提供人民币响应式网页。使用者以昵称和私人密码访问自己的数据，创建可用资金、投资和借贷账户，设置默认消费账户、日常消费额度和按日期自动扣除的固定支出。账户只在创建时填写初始金额；之后通过收支、转账、投资价值变动和借贷本金记录计算余额。首页汇总资产、负债、当月收支和实际可支撑月数，并与可调整的安全月数目标比较。

## User Stories

1. 作为使用者，我想用昵称和私人密码进入自己的财务空间，以便在手机和电脑上查看同一份数据。
2. 作为使用者，我想创建可用资金账户并填入初始金额，以便汇总随时可用于支出的资金。
3. 作为使用者，我想创建投资账户并填入初始价值，以便单独查看投资资产。
4. 作为使用者，我想创建借贷账户并填入未偿本金，以便了解负债和净资产。
5. 作为使用者，我想指定一个默认消费账户，以便日常记账不用每次选择账户。
6. 作为使用者，我想以金额和备注快速记一笔支出，以便保持低负担的日常记账。
7. 作为使用者，我想补记过去日期的支出，以便遗漏一天也能保持记录准确。
8. 作为使用者，我想修改或删除错误记录，以便账户余额和月度统计随之更正。
9. 作为使用者，我想看到日常支出自动减少默认消费账户和当月剩余额度，以便了解还能花多少。
10. 作为使用者，我想看到超支后的剩余额度为负数，以便清楚知道超出多少。
11. 作为使用者，我想设置默认的每月日常消费额度，并单独调整某个月，以便计划适应特殊月份。
12. 作为使用者，我想每月重新获得当月额度，以便上月结余或超支不会改变下月计划。
13. 作为使用者，我想配置房租、还贷等固定支出的金额和扣款日期，以便月度计划包含必要支出。
14. 作为使用者，我想固定支出在每月到期时自动扣默认消费账户，且只扣一次，以便余额反映已计划的付款。
15. 作为使用者，我想设在 31 日的扣款在短月的最后一天执行，以便每月都有对应记录。
16. 作为使用者，我想固定支出不占用日常消费额度，以便两类支出分开查看。
17. 作为使用者，我想手动记录工资收入并选择到账账户，以便实际到账增加该账户余额。
18. 作为使用者，我想手动记录理财收入并选择到账账户，以便已到账收益与投资价值变化区分。
19. 作为使用者，我想记录投资价值的上涨或下跌，以便投资账户随市场变化而更新，同时不误记为收支。
20. 作为使用者，我想在账户间记录转账，以便两个账户的余额准确变化且总资产不变。
21. 作为使用者，我想固定还款自动减少可用资金后，再记录其中偿还的本金，以便借贷余额准确且还款不重复计入支出。
22. 作为使用者，我想查看可用资金、投资资产、借贷余额和净资产，以便快速理解财务状况。
23. 作为使用者，我想查看当月实际收入、日常支出、固定支出和日常额度剩余，以便理解本月现金流。
24. 作为使用者，我想查看实际可支撑月数与安全月数目标的差距，以便判断储备是否达到自己的标准。
25. 作为使用者，我想把默认 6 个月的安全月数目标改成适合自己的数值，以便使用个人标准评估储备。
26. 作为使用者，我想在默认消费账户余额不足时仍看到自动扣款及负余额，以便发现资金缺口。
27. 作为使用者，我想所有日期和月度统计按中国时间显示，以便补记、扣款和月度计划一致。

## Implementation Decisions

- 使用现有 Next.js 项目实现响应式网页；数据持久化使用 PostgreSQL 和 Prisma。
- 首版仅支持人民币，金额以精确十进制或最小货币单位存储和运算，不使用浮点数计算余额。
- 以昵称识别使用者，并用私人密码验证；密码只存安全哈希。各类读写操作都限定在当前使用者的数据范围内。使用服务端会话，昵称本身不能访问数据。
- 没有密码找回或恢复码；界面应在创建账户时明确提示使用者妥善保存密码。
- 账户分为可用资金、投资和借贷。创建时填初始金额；创建后没有直接编辑余额的入口。余额由初始金额与已记录的变动计算。
- 默认消费账户只能选可用资金账户。日常支出只要求金额和备注，日期默认为当天，可修改为过去日期；提交后减少默认消费账户及发生月份的日常消费剩余额度。
- 允许更正和删除手动记录；更正后重新计算受影响的账户余额及月度统计。保留已发生的固定扣款记录，不因后来调整固定支出配置而改写历史。
- 工资收入和理财收入只记录实际到账，不维护预计收入；使用者手动填金额、类型、日期和到账账户。到账账户可以是可用资金或投资账户。
- 投资价值变动是投资账户的正负金额调整，不算实际收入或支出。转账是两个资产账户（可用资金或投资）之间的等额变动，不算收入或支出。
- 借贷账户保存未偿本金；固定还款扣除默认消费账户后，使用者单独记录该月偿还的本金，减少借贷余额且不再次扣现金。借贷余额不可小于零。
- 固定支出包含名称、金额、每月扣款日及启用状态。按中国时间到期后生成一笔自动支出；当月缺少配置的日期时使用月末。对同一固定支出和月份只生成一次，即使任务重试或应用重启。自动扣款可使默认消费账户为负。
- 固定支出的创建、修改、停用只影响未来扣款；已生成的历史记录保留。固定扣款计入当月实际支出，但不占用日常消费额度。
- 日常消费额度有默认月金额，可按月覆盖；每月剩余额度以该月额度减该月日常支出计算，不结转。
- 每月计划支出为该月启用的固定支出金额与日常消费额度之和。实际可支撑月数为当前可用资金总额除以当前月计划支出；预计或已到账收入均不从分母抵扣。安全月数目标默认 6，可修改。
- 计划支出为零时不显示无穷大的月数，而显示“暂无月度支出计划”；可用资金为零或负数时显示 0 个月并提示资金缺口。
- 财务概览显示可用资金、投资资产、借贷余额、净资产（可用资金＋投资资产－借贷余额）、当月实际收入和支出、当月日常额度剩余、实际可支撑月数及其与目标的差距。
- 自动扣款与手动写入应具备事务一致性，避免重复提交、部分转账或重复扣款。所有用户可见的日期按中国时间解释。

## Testing Decisions

- 测试以外部可观察行为为准：执行创建账户、记账、自动扣款、收入、转账和更正后，检查持久化数据和用户看到的余额与月度概览。避免只验证内部函数调用。
- 主要验收缝隙放在带测试数据库的应用操作流程上，覆盖昵称隔离、默认消费账户、各类余额变动和跨月统计。当前仓库没有同类测试可沿用。
- 对实际可支撑月数、短月末扣款、负余额、额度跨月重置、借贷本金和编辑/删除后的重算增加必要的边界测试。
- 验证同一固定支出在同一月份重复执行时只扣一次；转账失败时不应只更新其中一个账户。
- 手工检查窄屏与桌面布局，以及日常支出“金额＋备注”的快速输入流程。

## Out of Scope

- 银行或理财平台自动同步、实时行情、自动计算投资收益。
- 每日记账通知或其他提醒。
- 预计收入、自动工资或理财入账。
- 多币种、汇率换算。
- 完整的账户管理、邮箱或手机验证、密码找回。
- 借贷利息或摊还计划的自动计算；使用者记录实际偿还本金。
- 预算结转、复杂分类、报表导出。

## Further Notes

- 借贷月供是现金支出；偿还本金是负债减少，不应第二次减少现金或计入支出。
- 理财收入是实际到账；投资价值变动只改变投资资产价值。若资金在账户间移动，使用转账记录，避免重复计入总资产。
- 忘记密码且没有恢复方式时，使用者无法自行重新访问原有数据；这是首版明确接受的限制。
